# 原版聊天与新建任务界面对齐

Status: Confirmed

## Goal

让 Codex 引擎会话和导入历史沿用 ZCode 原版的文字、过程折叠和新建任务布局，减少切换引擎时的视觉差异。

## User Scenarios

1. 打开已导入会话，阅读正文并展开思考摘要与工具记录。
2. 点击新建任务，选择项目、填写提示并交给 Codex；返回首页后可继续打开旧会话。

## Scope

### In

- 原版问候与 Logo、居中输入卡、项目菜单及提示词入口。
- 原版用户气泡、正文宽度、间距、思考摘要折叠与工具详情。
- 历史附件包装的展示适配；原文和历史文件保持不变。
- 将源码更新到现有 GitHub 仓库，发布 alpha.3 的 macOS arm64 与 Windows x64 预览包。

### Out

- 引擎执行、登录和审批策略、自动任务能力变化。

## Constraints

- 草稿唯一所有者仍为 codexUiStore；引擎任务与历史仍由 ICodexService 提供。
- 项目切换复用壳层回调；提示词只填入草稿，不能自动安装插件或提交任务。
- 只展示引擎提供的可见思考摘要；没有时间数据时不编造耗时。
- 用原版现有组件和设计规范作为已确认设计，不另做风格探索。

## Acceptance Criteria

- AC-001: 新建任务显示原版问候、Logo、居中输入卡和项目选择，提示词点击只填入草稿；发送仍使用 Codex。
- AC-002: 导入与新会话的用户文字使用原版气泡和长文展开，助手 Markdown 使用完整正文宽度；文件引用、代码及图片仍可显示。
- AC-003: 思考摘要使用原版带图标的折叠与弱色文本，过程层级和间距与原版相符，工具详情保留真实状态和输出。
- AC-004: 原有历史快照内容不变；别名与真实模型 ID、首页往返、发送和重启恢复正常。

- AC-005: GitHub 源码及 alpha.3 预览版公开可读；Mac、Windows 包均来自同一提交，原生构建、安装或启动检查通过，公开下载与校验和一致，明确 Windows 验证边界。

## Decisions

- UI 仅做展示投影，不改写历史；格式明确的 Desktop 附件包装映射为文件入口与正文，无法确认格式时原样显示。
- 新建任务复用 ConversationDraftEmptyState、原版工作区菜单、ChatPromptEditor 和 ConversationDraftSuggestedPrompts；思考复用 Reasoning。
- 保留完整原始消息的复制入口，兼容快照与原生引擎历史共用同一展示组件。
